# 0013 手机创建／导入项目的目录操作

- 状态：已接受
- 日期：2026-11-10
- 范围：用户确认优先实现的创建／导入项目。

## 背景

DSH 基线的 `workspace/create` 可幂等登记已有目录。`directoryPicker/list` 和 `createDirectory` 要求 browse 后端；native 后端会拒绝，不能在手机上依赖电脑原生目录选择框。需要同时支持 Windows Desktop 和 Linux。

## 决策

- 插件用 Node 标准库提供有限的一级目录浏览、单个子目录创建和路径校验，不改变 DSH 的目录选择后端。
- 工作区登记仍由 `plugin/src/dsh/` 调用官方 Remote API，保持 ADR 0005、0007 的公开接口和外观层约束。
- 使用运行插件的系统账户权限，主目录只是起点。所有操作经过现有 TLS、设备认证和路由白名单。拒绝 UNC／设备路径，解析符号链接后的实际路径也必须满足本机路径规则。
- 只创建一个子目录，不覆盖同名项、不写文件内容、不删除、不执行 shell。
- 创建目录与登记分两步；部分成功后保留目录并允许重试登记，创建回执不明时先刷新确认。

## 理由

提供一致的手机操作流程，并保留桌面原有的目录选择方式。分步恢复避免误删目录，DSH 幂等登记避免重复工作区。

## 代价／后果

插件新增有限的文件系统能力，需要维护跨平台路径校验、数量限制和安全反向测试。已有设备 token 获得这三项明确列出的操作。完整文件管理、终端和 Git 操作仍独立规划。
