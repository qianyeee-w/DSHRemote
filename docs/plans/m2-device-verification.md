M2 的自动化测试（JVM 单元测试、`devServerTest`、真机上的 `connectedDebugAndroidTest`）已经覆盖了大部分逻辑。这份清单验证**只有在真机上才能确认的部分**，并把 `spec-v1.md` 的验收场景完整走一遍。

- 电脑端：Linux 开发服务器上的 dev-server（真实的 `dsh web` + 本插件 + 假模型，`192.168.3.26:3290`）。`m2-android.md` 第 6 节允许用 Linux 的 `dsh web` 代替 Windows 官方 Desktop。
- 手机：Xiaomi 22081212C（Redmi K50 Ultra），Android 17，通过无线调试连接开发服务器。
- 标记：【agent】由 agent 通过 adb 和 dev-server 完成；【你】需要用户亲自操作（锁屏、扫码、输入法、切换网络等）。
- 状态：✅ 已通过 · ⏳ 待验证 · ⚠️ 有问题（见备注）。

## 0. 准备

- 【agent】启动 dev-server：在 `plugin/` 下 `DSH_INSTALL_DIR=~/.cache/dsh-install npm run dev-server`。不要使用 3190 / 3191（用户自己的 dsh-web）。
- 【agent】安装 debug 包：`cd android && ./gradlew assembleDebug && adb install -r app/build/outputs/apk/debug/app-debug.apk`。
- 【agent】跑真机测试时加 `-Pandroid.injected.androidTest.leaveApksInstalledAfterRun=true`，否则跑完会卸载 App，配对丢失。
- 【你】手机解锁并保持亮屏；需要锁屏的步骤会单独说明。
- 手机上是中文输入法，`adb shell input text` 打不了字。需要在会话里发消息时，【agent】用 `npm run dev-server -- send <文字>`；「用手机输入法发消息」这一项由【你】来做。
- 查看手机上本 App 的通知：`adb shell cmd notification list | grep dshremote`。不要截通知栏，会截到其他 App 的通知。

dev-server 的真机验证工具（都用一台临时设备完成，做完立即撤销，不打印 token 和配对码）：

| 命令 | 用途 |
|---|---|
| `npm run dev-server -- send <文字>` | 给最近更新的会话发一条消息。`SHELL` 触发审批，`ASK` 触发提问，`STREAM`、`MARKDOWN` 流式输出 |
| `npm run dev-server -- decide allow\|reject` | 处理最早的一个待处理审批，相当于在 Desktop 上点了按钮 |
| `npm run dev-server -- impostor [--port 3292]` | 启动一个证书不同的 TLS 服务，模拟「这个地址现在是另一台设备」 |
| `npm run dev-server -- restart` | 重启 DSH（端口会变） |
| `npm run dev-server -- revoke <deviceId>` | 在配对页撤销设备 |

## 7. 结果

发现的问题：

- **改了地址后会话列表变空**（1.3）：地址变化时连接会重建，新连接从空状态开始，不在线期间列表是空的。现在重建时沿用上一条连接的会话和待处理事项（标为未连接），收到 `hello` 后整体覆盖。`ConnectionManagerTest` 已覆盖，变异测试能发现。

后台与网络的实际表现（Redmi K50 Ultra，Android 17，用户已关闭本 App 的电池优化）：

- **长时间锁屏**（4.5）：锁屏 1 小时、未充电，系统已进入深度 Doze（`dumpsys deviceidle` 为 `mState=IDLE`）。此时 App 进程仍在（运行了 1 小时 13 分钟，没有被杀），前台服务仍在前台。电脑上发起审批后约 4 秒，手机收到「需要你处理」的通知。
- **切换 Wi-Fi**（5.2）：重新打开 Wi-Fi 后约 2 秒恢复在线。
- 手机的无线调试在锁屏期间会断开，重新连接时端口会变（用 `adb mdns services` 查新端口）。这只影响 adb，不影响 App 的连接。

未在本次验证的：没有关闭电池优化时的表现、App 进程被杀后的恢复（不做开机自启，需要用户重新打开 App）。
