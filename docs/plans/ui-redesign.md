# 新版界面落地方案

状态：第一批（A1–A6）和 B1 已完成，下一项是 B2。第 7 节的问题都已确认。

设计依据是 [`docs/design/ui-redesign/`](../design/ui-redesign/README.md)（截图、可打开的样稿、规则说明）。它取代 [`android-visual-refresh.md`](android-visual-refresh.md) 里的视觉约定：点阵背景、按项目展开的首页、Inter 加思源黑体的字体组合都不再使用。

## 1. 范围

**做**：把设计里的十四屏落到 Android App 上，并补齐它们依赖的协议和插件能力。

**不做**：

- 会话搜索、文件管理、远程终端、通知按钮、云推送。它们仍在 `roadmap.md` 里，这一轮没有设计。
- 手机端的 Git 提交与撤销（`roadmap.md` 已记为不做）。
- 审批的「以后都允许」。DSH 没有这个能力（`protocol.md` 5.3）。
- 平板和横屏布局。

安全红线、ADR 和 `protocol.md` 的约束全部照旧。这一轮没有需要推翻的架构决策。

## 3. 第一批：只改 Android

### A1 主题、字体、通用组件

- `ui/Theme.kt`：按设计规格第 3、4 节换掉浅色配色和字号表。`StatusColors` 里去掉点阵背景相关的两项，增加「等你（字）」。
- `ui/Fonts.kt`、`res/font/`：中文和英文统一换成 IBM Plex Sans SC 的 Regular、Medium、SemiBold，去掉 Inter 和思源黑体；JetBrains Mono 补一个 SemiBold。字体从 IBM/plex 的官方发布包里取原始 TTF，不裁剪。`assets/font-licenses/` 同步更新。
- 体积：IBM Plex Sans SC 1.1.0 的 Regular 解包后约 8.5 MB，现在的思源黑体每个字重约 10.5 MB，所以三个字重换完，安装包不会变大。
- 保留现有的进程级字体缓存。上一次改版时，每次创建界面都重新加载多份约 10 MB 的中文字库，真机测试进程因此内存不足（见 `android-visual-refresh.md` 的结果一节）。
- Android 8、9 上的字体回退路径要单独看一眼：现在的实现对这两个版本走的是另一条分支。
- `ui/common/DesignComponents.kt`：补齐设计规格第 6 节的通用组件（状态标记、胶囊按钮、两行列表行、浮层、开关）。
- 深色配色按第 7 节问题 1 的答复处理。

测试：`test`、`lint ktlintCheck`、`assembleDebug`；真机跑 `connectedDebugAndroidTest`，并查看 APK 体积的变化。

### A2 会话页

涉及 `ui/chat/ChatScreen.kt`、`MessageViews.kt`、`ChatComposer.kt`、`ChatViewModel.kt`。

- **顶栏**：会话名加一行 `电脑名 · 项目名 · 审批方式`，数据都在现有的会话摘要和工作区列表里。去掉点阵背景。
- **正文和代码块**：按设计规格 6.5。代码块要给 Markdown 渲染库换一个自定义的代码块组件，并换成只有三种区别的高亮配色。
- **过程折叠**：把一轮里连续的思考和工具调用合成一行，展开后是步骤行（6.6）。动作和对象从工具的 `name` 和 `input` 得出，对应关系写成一个纯函数并配单元测试。
  - 暂时这样处理：协议里还没有轮次，先把两条用户消息之间的内容当作一轮。B1 之后改用真实的轮次。
  - 「改了几个文件」按 `edit`、`write` 的不同文件路径数计算。
  - 修改步骤的对比从 `edit` 的 `old_string`、`new_string` 得出（录制数据里有这两个字段）。插件会把每个字符串截到 2,000 个字符，被截断时在对比块末尾注明。
  - 命令输出先显示拿到的内容的最后 4 行。插件现在保留的是开头，B6 之后才是真正的末尾；在那之前，被截断的输出要注明「只拿到了前面一部分」。
- **输入框**：收起和展开两种状态，发送和停止合成一个键（6.3）。模型和审批方式放进展开后的第二行，沿用现有的选择逻辑。加号和发送键外圈先不显示。
- **发送状态**：气泡下的一行字，用现有的发送中、已发送、失败三种状态（6.4）。「不确定是否送达」在 B3 加。
- **运行状态行**和**每轮结尾**：先只显示正在做的那一步；用时和 token 等 B1、B4。

测试：过程分组和动作对应的单元测试；`ChatContent` 的界面测试覆盖折叠和展开、输入框两种状态、发送键三种状态；改完在真机上看长代码、长 Markdown 和键盘弹出时的布局。

### A3 审批和提问面板

涉及 `ui/attention/AttentionCard.kt`、`AttentionScreen.kt`、`AttentionHandler.kt`，以及 `ChatScreen.kt` 里放面板的位置。

- 审批面板按设计规格 7.4，提问面板按 7.5。
- **只有一个问题且是单选时，点选项直接提交。** 多选或多个问题时保留「回答」按钮。自己写的答案从下面的输入框提交，对应协议里的 `custom`。提交前的本地校验沿用 `AnswerForm`。
- 提交中、已在别处处理、失败这几种状态的提示保留，样式跟着面板走。
- 从通知点进来：事项属于某个会话时，打开那个会话，面板就在底部；不属于任何会话时（子代理发起的），用只有返回键的独立页面放同一个面板。

需要先验证的一件事：有审批或提问等着的时候，从输入框发消息，DSH 会怎么处理。验证结果决定占位文字「或者告诉它换个做法」是否成立；不成立就在等待期间禁用输入框。

**结论（2026-11-13，用户确认）**：有审批在等的时候 DSH 停着等审批，发的消息改变不了这次审批，所以「或者告诉它换个做法」不成立，审批等待期间输入框不可用（只留停止），占位文字是「先处理上面的审批」。提问不受影响：输入框里写的是答案（`custom`），不是普通消息。多个问题、多选时（设计没画）用户确认：只有一个问题时用底部输入框写答案，多个问题时每题下面一个小输入框，底部输入框暂时不可用。

测试：现有的审批安全测试全部保留；补「单选直接提交」「多选需要确认」「别处已处理后面板收起」的测试；`devServerTest` 里的审批用例照跑。

- 卡片里直接处理审批和提问，复用 A3 的提交逻辑和它的全部状态处理。
- 项目筛选的选择记在本地设置里。
- 顶栏的电脑名和菜单在 A6 做，这里先放名字。**不放搜索图标。**
- 导航变化：配对了多台电脑时，首页不再先进电脑列表，而是直接显示上次使用的那台（见第 7 节问题 2）。
- 暂时这样处理：
  - 最近列表的第二行只显示项目名（靠左），等 B1 有了最后一句话和结果状态，再改成设计里的样子。
  - 运行中的第二行写「运行中」。
  - 未读加粗、重连提示、「N 条未读」等 B2。

测试：分段和筛选的单元测试；`SessionListContent` 的界面测试覆盖卡片里的允许、拒绝、选项直答；`devServerTest`。

### A5 新任务

涉及 `ui/sessions/SessionListScreen.kt`（现在的新建会话对话框）、`SessionListViewModel.kt`，以及保留不动流程的 `ProjectFlow.kt`、`ProjectPicker.kt`。

- 首页底部的输入框原地展开（设计规格 7.6），取代新建会话对话框。
- 开始一个任务是三步：创建会话；模型或审批方式和默认值不同时分别设置；发出第一条消息。三步用到的都是现有接口。
- 中途失败时的处理要写清楚并有测试：会话已创建但后面的步骤失败时，进入这个会话，把文字留在输入框里并提示失败，不重复创建会话。重发消息沿用同一个 `requestId`。
- 项目列表最后一项进入现有的创建／导入流程，那个流程只换样式。

测试：视图模型的单元测试覆盖三步全部成功和每一步失败；界面测试覆盖展开、收起后内容保留。

**用户确认（2026-11-13）**：第一条消息发送失败时，进入会话显示成发送失败的气泡，「重试」沿用同一个 requestId（不是放回输入框：那样重发是新的 requestId，第一次其实已经送到时会发两次）。项目列表保留「不指定项目」，放在「新建或导入项目」上面。

要改的地方：

## 4. 第二批：先改协议，再改插件，再改 App

每个任务都从修改 `docs/protocol.md` 开始。下面写的字段是建议，以实施时对真实 DSH 的验证为准。

### B1 轮次与执行结果

这是第二批的基础。`research/dsh-session-api.md` 9.5 已经指出：准确的结束状态、本轮用量、分支位置、整轮折叠都需要轮次数据，应该一起设计，不要各自猜边界。

- **协议**：消息归属到轮次；每个轮次有编号、开始和结束时间、结束原因（正常结束、失败、被停止）。会话摘要增加最近一轮的结果和最后一句回复的开头。
- **插件**：在适配层从 DSH 的 `turn/start`、`turn/end` 得出轮次；不向手机透传原始事件。
- **App**：
  - 首页最近列表的第二行按设计显示（最后一句话、失败、已停止）。
  - 会话页每一轮的结尾显示结果和用时；过程折叠改用真实的轮次。
  - 「结果待确认」由 App 判断：断线前还在运行、重连后还没拿到新状态时显示。
  - 任务结束的通知措辞跟着真实结果走，不把「运行结束」说成「完成」。
- dev-server 的假模型加一个能让一轮失败的关键词，供测试用。

测试：插件的单元测试用录制数据；契约测试和端到端测试覆盖正常结束、失败、被停止；App 的 `devServerTest`。

### B2 未读结果与离线补看

只改 App，依赖 B1。

- 每个会话记一个「上次看到的时间」，存在本地。有比它新的结果、而且不在运行中，就算未读。
- 重连后算出离线期间新出现的结果数，显示重连提示。
- 「N 条未读」筛选。
- 通知：重连后不为离线期间的旧结果逐条补发通知。规则写进 `NotificationRules` 并配测试。

用户确认（2026-11-14）：离线 5 分钟以上重新连上才提示；离线期间没有新结果时不提示；只把未读的失败排在最近列表前面，看过之后回到按时间排。

### B3 草稿与发送状态

只改 App。

- 每个会话的草稿存在本地，回到会话时恢复；首页显示「草稿：…」。
- 发送状态增加「不确定是否送达」：请求发出后没有收到回应时进入这个状态，给出「查看」（刷新会话）和「重发」。
- **不自动重发。** 插件只在 10 分钟内按 `requestId` 去重，而且重启后记录会清空，所以超时之后的重发必须由用户决定。

测试：`Outbox` 的单元测试覆盖新状态；反向用例是「回应丢失时不会自动发第二次」。

用户确认（2026-11-14）：首页新任务里写了一半的字不算草稿（不属于任何会话，仍只在 App 运行期间保留）；请求体已经写出、但没拿到回应（超时、断开）算「不确定」，连接都没建立起来算「失败」；草稿不设时间上限，电脑上删掉的会话的草稿跟着清掉。

### B4 用量与上下文

`research/dsh-session-api.md` 9.2、9.3 认为可做，但相关接口还没有做过运行时契约测试，要先补。

- **协议**：按会话读取用量。建议包含上下文的估算占用和上限、整个会话的输入输出和缓存读写、本轮用量（拿得到时）。
- **插件**：只提取这几项，不透传 DSH 的全部统计。
- **App**：发送键外圈、长按出现的用量卡片、每轮结尾和运行状态行里的 token 数（设计规格 6.3、6.7、7.11）。
- 口径照调研文档：缓存命中率的分母是未缓存输入、缓存读取、缓存写入之和，分母为零不显示；上下文占用标「约」；拿不到的项不显示，不能显示成 0。

用户确认（2026-11-14）：本轮用量照抄 DSH 官方界面的算法（`deriveTurnTokenUsage`，MIT）到插件，口径和官方一致；运行中的状态行这次不显示「约 N token」，只在这一轮结束后在结尾显示准确的用量。

### B5 计划

先调研：DSH 有没有公开的计划或目标数据。调研文档里没有这一项。

- 有公开数据：定协议，做计划条和计划页（设计规格 6.9、7.12）。
- 没有：这一项不做，不从回复的文字里猜计划。把结论写进调研文档。

调研结论（2026-11-14，调研文档 9.3b）：有公开数据。`todos` 是模型这一轮的任务清单（每轮开始时 DSH 清空），`goal` 是长期目标（含受阻原因）；`plan` 投影只是计划模式的开关。用户确认：「最近进展」DSH 没有对应数据，这次不显示；首页运行中一行的「第 3 步，共 5 步」这次不做；只有目标、没有步骤时，计划条显示「目标 · 目标开头」，目标受阻时用琥珀色。

### B6 命令输出保留末尾

- 现在插件把工具输出截到 8,000 个字符，保留的是开头。命令的结果通常在末尾。
- 协议和插件改成对命令输出保留末尾（或者开头和末尾各留一段），并标明截掉的位置。
- App 的命令输出块改成真正的「最后 N 行」。

- **B6 命令输出保留末尾（2026-11-14）**
  - 做法按方案的「开头和末尾各留一段」：`bash`、`pwsh` 的输出超过 8,000 个字符时，插件保留开头约 1,000 个字符和末尾约 7,000 个字符，尽量切在换行处、不切开代理对，末尾不加「…」，并给出 `omitted: { offset, chars, lines }`（protocol.md 5.2）。其他工具仍然保留开头。实测 DSH 本身不截断命令输出（调研文档 9.3c）。
  - App：`commandOutput` 把输出拆成开头、去掉的行数、末尾；命令输出块默认是真正的最后 4 行，「全部 M 行」的 M 是原来的总行数，展开后在开头和末尾之间写琥珀色的「⋯ 中间省略了 K 行 ⋯」；不再提示「只拿到了前面一部分」（旧插件时仍然提示）。
  - 顺手修的：B5 推送后 Windows 上的契约测试失败，原因是假模型的 `TODO`、`GOAL` 用会话第一轮的 `lastText` 判断，Windows 上 DSH 注入的上下文不同；另外生成标题的请求也被回了工具调用。改为用整条用户内容判断，并且只在请求提供了对应工具时才调用（单独的提交）。真机测试还发现展开后的输出块嵌套了横向滚动，会让 Compose 直接报错，改成只在外层滚动。
