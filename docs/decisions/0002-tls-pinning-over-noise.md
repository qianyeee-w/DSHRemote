# 0002 使用 TLS + 证书指纹固定，不用 Noise

- 状态：已接受
- 日期：2026-11-07

## 背景

App 和插件之间需要加密和身份认证。候选方案有两个：TLS 加证书指纹固定，以及 Noise 协议（ds-harness-remote 用的是 Noise_IK）。

## 决策

使用 **TLS + 证书指纹固定 + 配对时下发设备 token**。

- 插件生成自签名证书，App 只认二维码里的公钥指纹（SPKI SHA-256）。
- 手机的身份由配对时下发的设备 token 认证。

## 理由

- 两端都有成熟的实现（Node 的 `tls` 模块、Android 的 OkHttp），需要自己写的加密代码最少。
- 可以直接沿用 HTTP 和 WebSocket，插件的转发逻辑最简单。
- 以后即使加了中转服务器，只要中转只负责原样转发字节，TLS 仍然是两端直连的。

## 代价 / 后果

- TLS 本身只认证服务器，客户端认证要靠 token 另外实现。
- 最大的实现风险是指纹校验写错，比如写成信任所有证书。这类代码必须有反向测试，合并前必须人工审查。
- 如果以后需要一台能理解消息内容的中转服务器（例如按会话分发、离线排队），再考虑 Noise 这类应用层的端到端加密。到那时优先参考或兼容 ds-harness-remote 已经公开的协议。
